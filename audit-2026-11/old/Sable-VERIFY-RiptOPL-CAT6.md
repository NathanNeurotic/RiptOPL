## 2. Full reasoning — REFUTED (2)

### RIPTOPL-513 — REFUTED (parent re-checked)

**As filed:** in `sceAtaDmaTransfer`'s LBA48 branch, `hdpro_atad.c` computes `lcyl = (lba >> 8) & 0xff` and `hcyl = (lba >> 16) & 0xff` (the "28-bit forms") instead of `atad.c`'s packed forms, so "LBA bits 32-47 are silently dropped and sectors at or above 2^32 (2 TiB) alias onto low sectors"; fix = copy `atad.c`'s two lines in.

**Defeating evidence:**

1. The HDPro function's LBA parameter is 32 bits. `int sceAtaDmaTransfer(int device, void *buf, u32 lba, u32 nsectors, int dir)` — `modules/iopcore/cdvdman/hdpro_atad.c:678`, and the shared prototype is the same for both variants: `modules/iopcore/cdvdman/atad.h:55`. The code even says so at the cited site: `hdpro_atad.c:695` — `/* Variable lba is only 32 bits so no change for lcyl and hcyl. */` There are no bits 32-47 in the function to drop.
2. For a 32-bit `lba` the cited composition is *correct*, including the LBA48 double-write in `sceAtaExecCmd` (`hdpro_atad.c:482-498`), which writes `(lcyl >> 8)` / `(hcyl >> 8)` on the first pass and the low bytes on the second. With `lba < 2^32`, the true first-pass LCYL byte (LBA bits 32-39) and HCYL byte (bits 40-47) are both zero — which is exactly what `lcyl = (lba >> 8) & 0xff` and `hcyl = (lba >> 16) & 0xff` produce. The one register that does carry high bits in range, `sector` (bits 24-31 in its high byte), *is* composed the packed way at `hdpro_atad.c:702`, matching `atad.c:680`.
3. The prescribed fix is an identity transformation. Substituting `atad.c:681-682` with a `u32 lba`: `((lba >> 24) & 0xff00)` is 0 and `((lba >> 32) & 0xff00)` is 0 — both expressions reduce to exactly the current `lcyl`/`hcyl` values. Copying the lines in changes no register value.
4. The ≥2^32 aliasing the finding describes cannot be produced by these two lines: it would occur, if anywhere, at the `u32` parameter conversion shared by *both* variants (`atad.c:659-661` also takes `u32 lba`). That is an interface-width limitation of `sceAtaDmaTransfer` as declared in `atad.h:55`, not the cited LCYL/HCYL composition defect, and it is not what the finding claims or what its fix addresses.

The mechanism as filed — wrong LCYL/HCYL composition dropping bits 32-47 — is absent.

### RIPTOPL-443 — REFUTED (parent re-checked)

The finding's arithmetic is correct and was re-derived, not trusted:

- `FIDs` is declared `u16 FIDs[ISO_MAX_PARTS]` in the shared macro at `modules/iopcore/common/cdvd_config.h:71`, used by all three variants.

- `smb_CloseAll` has exactly one caller: `DeviceUnmount` in `modules/iopcore/cdvdman/device-smb.c:163-169` (grep-verified: the only call site in the tree is `device-smb.c:166`).

## 5. New finding filed by this pass

### RIPTOPL-602 — `hddFormat` reads a cache entry's sector after freeing the entry (second instance of the RIPTOPL-467 pattern)

- **Category:** 6 (bug, latent)
- **Locations:** `modules/hdd/apa/src/hdd_fio.c:435` (`apaCacheFree(clink)`) and `modules/hdd/apa/src/hdd_fio.c:438` (`clink->sector` passed to `hddAddPartitionHere`), inside `hddFormat` (`hdd_fio.c:321…`), in the `#ifdef APA_FORMAT_WIPE_COMMON_ONLY` branch
- **Problem:** `clink` is obtained from `apaFindPartition(f->unit, "__sysconf", &rv)` at `hdd_fio.c:433`, released with `apaCacheFree(clink)` at `:435`, and then dereferenced — `clink->sector` is passed as the start sector for the new `__common` partition at `:438`. This is the same free-then-read pattern as RIPTOPL-467 (the `apaOpen` instance at `hdd_fio.c:510-512`, verified above) at a second site that finding did not cite. It is benign today by the same contract: `apaCacheFree` only decrements `nused` and relinks the entry into the cache free list (`modules/hdd/apa/src/cache.c:176-192`) — the memory is a static cache array — and no cache allocation intervenes between `:435` and the argument evaluation at `:438` (only `memset`/`strcpy` on `params.id`). Any future change that allocates a cache entry in that window, or makes `apaCacheFree` actually release/reuse storage, silently turns the `__common` partition's start sector into whatever the reused entry holds, on a format path. Scope note: the branch compiles only in the `APA_XOSD_VER` build variant (`APA_FORMAT_WIPE_COMMON_ONLY` is defined at `modules/hdd/apa/src/apa-opt.h:28`, under `APA_XOSD_VER` at `:26-29`); the default build does not contain this instance. RIPTOPL-467's instance, by contrast, is in the default build (`APA_ENABLE_PASSWORDS 1`, `apa-opt.h:36`).
- **Fix:** Hoist `u32 sector = clink->sector;` above the `apaCacheFree(clink)` at `:435` and pass `sector` at `:438` — the same reorder RIPTOPL-467 prescribes for `apaOpen`. One local, no new code paths.
- **Benefit:** Removes a latent use-after-free on the XOSD format path at zero cost, and closes the pattern family rather than leaving a second instance of a filed defect in the tree.
- **Effort:** S · **Risk:** Low · **Confidence:** High (ordering and branch condition READ at the pin by two independent readers; the "can it bite" half is latent-by-contract, as with RIPTOPL-467)
