## Candidate finding

### [R4-3-1] Ethernet link-mode from the config file indexes a 4-entry table in ee_core with no range check
- **Category:** 6 (bugs/security)
- **Locations:** `ee_core/src/util.c:74` (`static const char *SmapLinkModeArgs[4]` — actually a function-local array at :74-79), guard at `ee_core/src/util.c:96` (only `config->g_ps2_ETHOpMode != ETH_OP_MODE_AUTO`), indexing copy at `ee_core/src/util.c:99` (`strncpy(&g_ipconfig[g_ipconfig_len], SmapLinkModeArgs[config->g_ps2_ETHOpMode - 1], 6);`). Producer chain, all READ: `src/app/settingsio.cpp:1924` (`configGetInt(configNet, CONFIG_NET_ETH_LINKM, &gETHOpMode);` — no clamp), `src/platform/system.cpp:1561` (`config->g_ps2_ETHOpMode = gETHOpMode;` — int narrowed to the `unsigned char` field at `ee_core/include/coreconfig.h:46`, still unclamped). Valid values are 1–4 (`include/opl.h:109-113`: AUTO=0, 100M_FDX, 100M_HDX, 10M_FDX, 10M_HDX; `ETH_OP_MODE_COUNT` = 5 is a count, not a mode).
- **Problem:** The link mode is an integer in the user's hand-editable network config file. The GUI's enum widget constrains values set interactively, but nothing on the file-load path validates the range: `configGetInt` stores whatever the file says. A value of 5 (or 9, or 200) survives the trip into ee_core, passes the `!= AUTO` test, and indexes `SmapLinkModeArgs` out of bounds — index 4 for mode 5, up to index 254 for a byte value of 255. `strncpy` then copies 6 bytes from whatever the wild pointer value points at (the "pointer" is adjacent static data interpreted as an address) into the SMAP ipconfig argument string, or faults. The failure lands inside `set_ipconfig()`, which runs on every ee_core init for network modes — a malformed config value turns into undefined behaviour at game launch instead of a rejected setting. Same trust-boundary shape as RIPTOPL-016 (config-file strings trusted into fixed fields), one layer deeper: this one is an integer, and it crosses into ee_core.
- **Fix:** In words: clamp where the value is consumed — in `set_ipconfig`, treat any mode outside 1–4 as AUTO (skip the link-mode args), or clamp `gETHOpMode` to the enum range where it is loaded at settingsio.cpp:1924. One comparison at either end; the ee_core end is the one that cannot be bypassed by another producer.
- **Justification (fix adds a check):** it is a single range comparison on a cited out-of-bounds index driven by a user-editable file — the minimum that removes the defect, following the audit rule for added checks.
- **Benefit:** A hand-edited or cross-version config value stops being an out-of-bounds read at every network game launch.
- **Effort:** S · **Risk:** Low · **Confidence:** High (READ — full chain read: settingsio load site, system.cpp assignment, coreconfig field type, opl.h enum, util.c consumer)
