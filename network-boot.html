Network (SMB / NFS / UDPFS / UDPBD)

Every network protocol is on this page: SMB shares, NFS exports, and UDPFS and UDPBD, which stream PS2 games from a PC. UDPFS and UDPBD launch through Neutrino by default; their games (UDPFS Files and IMG, and UDPBD) can also run on OPL's own core, per game. Set Network Connectivity (Off / Manual / Auto) in Game Sources and choose the Protocol indented under it (the same row is on the Network page). The picker contains SMB / UDPFS / UDPBD / HTTP / NFS. SMB and NFS use OPL's own core unless a game is set to Neutrino; HTTP uses OPL's own core and has separate setup and limits.

Four rows, Off by default
The old Network Boot ON/OFF toggle and the separate Net Boot Protocol picker are retired placeholders. The network is now four rows. Network Connectivity, on Game Sources, is an Off / Manual / Auto start mode and defaults to Off (no network device). Protocol chooses SMB / UDPFS / UDPBD / HTTP / NFS; it sits indented under Network Connectivity on Game Sources and on the Network page, as one setting. Access, on the Network page, qualifies the chosen protocol (for SMB, SMB Version picks SMBv1 or SMB2/3; NFS has NFS Export and NFS Writes). Turning Connectivity Off keeps your protocol for when you turn it back on. UDPFS needs a static PS2 IP and a matching PC-side server. Pick a protocol only when you have those pieces in place. Local devices (USB / internal HDD / MMCE) are independent and browse alongside whichever network protocol you choose.

The Network rows

Game Sources holds Network Connectivity with Protocol indented under it. Network holds the same Protocol row, plus SMB Version and Access, and NFS Export and NFS Writes while Protocol is NFS. SMB Version (SMBv1 / SMB2/3) is editable for SMB. Access is Files/IMG for UDPFS, locked to Files for SMB/HTTP/NFS and IMG for UDPBD. The first protocol can start while the NIC is unused; switching an already loaded protocol requires restarting RiptOPL.

PS1 network libraries
UDPFS Files lists uppercase POPS/*.VCD and POPS/*.cue games alongside Ember titles and can automatically equip Okeanos's .udpfs pair. The POPSTARTER driver (UDPFS Assault 1.0.1) reads every POPS file, builds a VCD from a cue sheet on the fly and writes VMC saves on the server, with no USB device involved, so the server must allow writes. The VCD handoff has not been tested on a real console. UDPBD and UDPFS IMG remain Ember-only for PS1, and so does NFS: POPSTARTER resets the I/O processor and has no NFS driver, so .VCD games over the network need SMB or UDPFS Files. See POPS UDPFS setup and PS1 over NFS.
Apply and retry without leaving the page
Confirming Network Settings applies the current values and begins a new connection attempt immediately. If a router or server was slow and the page reports a failed connection, press Select / Refresh on that network page to retry it; reopening settings or saving every setting is no longer required.

UDPFS is the one modern network-boot protocol (Rick Gaiser's UDPRDMA transport). It comes in two shapes, chosen with the Access row (see the comparison below): Files (the udpfs_ioman filesystem, loose ISOs) or IMG (the udpfs_bd block device, a served disk image). It has no DHCP client and needs a static PS2 IP; if neutrino.elf is missing at launch, OPL warns and returns to the menu.

UDPBD vs UDPFS — pick by your PC server
UDPBD (the older SUDPBDv2 udpbd.irx protocol) is a first-class fourth choice, not retired — it is kept because SUDPBDv2 is wire-incompatible with UDPRDMA (UDPBD speaks port 0xBDBD via udpbd-server; UDPFS speaks 0xF5F6 via udpfsd), so users still running the old udpbd-server must be able to keep selecting it. A config saved as UDPBD stays UDPBD — RiptOPL never silently migrates you off it. If you are setting up fresh, UDPFS can serve loose ISOs as well as disk images. See the format limits below before relying on server-side decompression.
UDPBD, UDPFS and SMB work on a real PS2
All three have launched games on real hardware from PS2 Servers. The UDPBD test (2026-09-26, Kingdom Hearts) used every Neutrino setting at its default — Neutrino Path blank (RiptOPL found neutrino.elf inside the served image) and no per-game filesystem or arguments. For an ordinary FAT/exFAT image with your games in DVD/, leave the game's Neutrino Filesystem on Auto: bd treats the whole block device as the disc, which only fits a server exporting a single raw ISO. NFS has not been tested on a real PS2 yet.

SMB Version

When Protocol = SMB, the SMB Version row selects the dialect OPL's core speaks: SMBv1 or SMB2/3 (SMB 2.0.2 or 2.1, with an unsigned SMB 3.0 fallback). A new install starts on SMB2/3, since Windows 10 and 11 ship without SMBv1; a settings file from before this row keeps SMBv1, which every older build used. It applies to both halves of SMB, browsing the share from the menu and reading the game in game. The row is greyed unless Protocol is SMB, and its value is kept while greyed. SMB 3.x is not a separate choice: under SMB2/3, SMB 3.0 is tried only when the server refuses 2.x, and a server that accepts only SMB 3.1.1, or refuses 2.x and requires signing on SMB 3.x, is not reached. The server must speak the dialect you pick: an SMBv1-only server lists nothing under SMB2/3, and an SMB2/3-only server lists nothing under SMBv1. A game on the Neutrino core does not use this row: Neutrino logs in with its own SMB 3.0 client on TCP 445 (see SMB through Neutrino).

Switching protocols with saved settings

UDPFS remembers its own Files/IMG choice independently of UDPBD, which always uses IMG. Switching to UDPBD and back should restore your previous UDPFS choice; a fresh configuration defaults to Files. Set Access on the Network page and make sure the PC server serves the matching folder or disk image.

Once a network driver has loaded, changing its protocol or UDPFS Access requires a restart. If restarting the application leaves the old connection active or the new protocol unavailable, fully restart the console and relaunch RiptOPL with the saved settings. Deleting your configuration is not the normal way to apply a protocol change. For a report, record both the old and new protocol, UDPFS Access, whether you restarted the application or console, and the server version.

Access — Files vs IMG

The Access row is on Settings → Network, alongside Protocol. Game Sources shows Connectivity and Protocol, but no Access row. Access is only free to change while Protocol = UDPFS — under SMB it is value-locked to Files and under UDPBD to IMG, greyed in both cases. Its two values are Files (default) and IMG. They are the same UDPFS protocol in two shapes: Files is the udpfs_ioman filesystem (udpfs:), IMG is the udpfs_bd block device (massN:).

Both ride the same UDPRDMA transport and the same server — pcm720/udpfsd, a single prebuilt Go binary (no Python) that serves both; just pass -fsroot <dir> for Files (the filesystem) or -bdpath <image> for IMG (the block image).

No PC on the network? udpfs-server by YouKnow-sys is an Android app that serves the same thing from a phone or tablet — folders or disk images, so it covers both Files and IMG. It is found by broadcast, so there is no server address to type in on the console, and it works over a router or a direct cable. Built on the same udpfsd underneath; MIT licensed.

Whichever server you use, a UDPBD-only udpbd-server (SUDPBDv2) will not talk to either backend. Because both backends bind the same UDPRDMA port and the IOP can load only one per boot, you can't run both at once — Files vs IMG is a config-time choice, and switching between them needs an OPL restart to take effect (OPL shows the usual restart-to-apply notice).

  • Files launches with the stock -bsd=udpfs, which loads Neutrino's shipped bsd-udpfs.toml (the FHI filesystem driver, udpfs_ioman / udpfs_fhi). Neutrino opens the game by name (-dvd=udpfs:<name>) — no massN: block device, no fragment list. On the nightly Neutrino the -bsd is auto-detected.
  • IMG launches with -bsd=udpfsbd, a RiptOPL-private token: Neutrino ships udpfs_bd.irx but no stock -bsd for it, so RiptOPL auto-places config/bsd-udpfsbd.toml into the bundled Neutrino folder. The private name is deliberate — it avoids colliding with stock's bsd-udpfs.toml (a different driver), so the block config and the stock filesystem config coexist on one install.
So why offer both Files and IMG?

They're the same protocol but a genuinely different workflow. Files is the lower-friction, "modern" model (loose ISOs, drop-in, server-dependent virtual ISO exposure (see the format limits below) compression) and matches how NHDDL and pcm720's server are designed. IMG reuses OPL's existing massN: block pipeline (a disk image the PS2 mounts with its own FAT/exFAT drivers) — handy if you already keep a block image or want the exact same shape as USB/HDD. Pick whichever fits how you store your games. (If you already run the old udpbd-server, that's a separate UDPBD choice — see above — not a UDPFS mode.)

Which PC-side UDPFS server do I run?

The RiptOPL release ships Neutrino as a drag-and-drop neutrino/ folder, but it does not embed PC server software. Open PS2-Servers.url from the package or visit PS2 Servers for the maintained SMB, NFS, UDPFS, UDPBD and HTTP all-in-one launcher, then choose UDPFS and follow its protocol-specific settings. Advanced users can instead run pcm720/udpfsd directly: pass -fsroot <dir> for Files or -bdpath <image> for IMG. The standalone udpbd-server speaks SUDPBDv2 and does not work with UDPFS; use it only with the separate Protocol = UDPBD choice.

Why does UDPFS IMG need a private bsd-udpfsbd.toml when a stock bsd-udpfs.toml exists?

The -bsd token is just a config filename: at game boot Neutrino loads config/bsd-<token>.toml, and the toml's body picks the IOP driver. Stock Neutrino already ships a bsd-udpfs.toml whose body is the FHI filesystem driver (udpfs_ioman / udpfs_fhi, no i_bdm, registers no massN: block device). The Files mode uses that stock token as-is — -bsd=udpfs, opening the game -dvd=udpfs:<name> by name.

The IMG mode needs the block-device body instead (udpfs_bd.irx, i_bdm → massN:) because that launch hands Neutrino -dvd=massN:. Neutrino ships udpfs_bd.irx but no built-in -bsd token for it, so RiptOPL auto-injects config/bsd-udpfsbd.toml into the bundled Neutrino folder at build time and emits -bsd=udpfsbd. The private name is deliberate — bsd-udpfsbd.toml will not collide with stock's bsd-udpfs.toml (a different driver), so the block config and the stock filesystem config coexist on one Neutrino install. If you assembled Neutrino yourself, copy neutrino/bsd-udpfsbd.toml from the RiptOPL source tree into your neutrino/config/ folder.

Requirements

  • Static PS2 IP address (UDPFS and UDPBD). Their IOP modules (UDPFS in both Files and IMG) have no DHCP client — they read the static IP fields in Settings → Network and use them directly. While either is the Protocol, RiptOPL locks IP Address Type to Static and enables those fields; your DHCP choice is kept as the SMB/NFS/HTTP preference and comes back when you switch protocol. If DHCP is that kept preference, RiptOPL says so when you select a UDP protocol and again as a boot notice. (SMB can use DHCP or a static IP; it keeps its own address/port/share/credentials fields on the Network page, hidden automatically when either UDP protocol is selected.)
  • PC-side UDPFS server running on the same LAN, matching the Access mode you chose. RiptOPL does not embed one. Open the package's PS2-Servers.url shortcut or visit PS2 Servers for the maintained SMB, NFS, UDPFS, UDPBD and HTTP all-in-one launcher. Advanced users can run pcm720/udpfsd directly. The standalone udpbd-server (SUDPBDv2) does not work with UDPFS — it belongs to the separate Protocol = UDPBD choice.
  • Neutrino ELF for UDPFS. UDPFS Files and IMG launch via Neutrino by default and fall back to OPL's own core without it (see Which core runs a network game). The UDPFS feature ships its own bundled Neutrino (a ready-to-use neutrino/ folder in the release zip, pre-populated with the UDPFS config). See Neutrino Core. (SMB and NFS need no Neutrino: they use OPL's own core unless a game is set to Neutrino.)
  • UDPFS runtime IP: RiptOPL rewrites the active Neutrino TOML's ip= value from the configured PS2 static IP before launch. Files uses config/bsd-udpfs.toml; IMG uses config/bsd-udpfsbd.toml. Keep that configuration writable and retain its expected IP token. A missing or unreadable required TOML aborts before teardown. A restructured, oversized or unwritable file is logged and left under the existing manual-IP contract; verify its IP yourself in that case.
  • Game files laid out with standard OPL folders for the IMG mode, SMB and NFS: CD/, DVD/, ART/, CFG/, etc. — the same structure you would use on a USB drive. UDPFS Files also expects the standard layout: its served directory must contain CD/ and DVD/ subfolders (OPL lists from <served>/CD + <served>/DVD, never loose ISOs at the served root); drop an ISO into CD/ or DVD/ and the game appears.

Selecting a network protocol

Set a static IP on the PS2 (UDPFS and UDPBD)

For UDPFS (either access mode) or UDPBD, go to Settings → Network and set a fixed IP address, subnet mask, and gateway. You do not have to turn DHCP off: selecting either UDP protocol locks IP Address Type to Static, and if you use DHCP for SMB or HTTP that choice is kept and comes back when you switch protocol. The UDP IOP modules read this address at module-load time and have no way to acquire a lease later.

Pick your Network Protocol (and Access)

In Settings → Game Sources, set Network Connectivity to Manual or Auto, and set the Protocol under it (or on Settings → Network) to SMB, UDPFS, UDPBD, HTTP or NFS. Set Network Connectivity back to Off to disable networking; the protocol is kept for when you turn it back on. When Protocol = SMB, pick the SMB Version: SMB2/3 (a new install's default) or SMBv1. The Access row (Files / IMG) is always present, but it is only free to change under UDPFS: under SMB, HTTP and NFS it is locked to Files and under UDPBD to IMG, greyed in both cases. Because the PS2 has a single NIC, choosing one excludes the others automatically. Save settings. When UDPFS is selected, SMB's server / port / share / credentials fields on the Network page are hidden automatically. Switching between Files and IMG needs an OPL restart to take effect (only one UDPFS backend can bind the transport per boot).

Start the PC server

Open PS2-Servers.url from the RiptOPL package or visit PS2 Servers. In its all-in-one launcher, choose the card that matches RiptOPL's Protocol row: SMBv2 or SMBv3 for SMB on SMB2/3 (SMBv1 for SMB on SMBv1), NFS, UDPFS, or UDPBD. Select the games folder or disk image, click Start, and follow the protocol-specific settings the launcher displays.

Advanced: run pcm720/udpfsd directly

For UDPFS only, advanced users can run pcm720/udpfsd in the mode that matches the chosen access mode. Files serves a directory containing CD/ and DVD/ subfolders; IMG serves a FAT/exFAT disk image.

# UDPFS Files — a folder with CD/ and DVD/ subfolders of ISOs
udpfsd -fsroot /path/to/games            # Files   (Linux/macOS)
udpfsd.exe -fsroot C:\path\to\games      # Files   (Windows)

# UDPFS IMG — a served FAT/exFAT disk image
udpfsd -bdpath /path/to/games.img        # IMG   (Linux/macOS)
udpfsd.exe -bdpath C:\path\to\games.img  # IMG   (Windows)

Boot the PS2 and find your games

RiptOPL loads the IOP module as soon as it starts. UDPFS Files mounts the udpfs: filesystem; UDPFS IMG mounts the served image as massN:. Your games appear in the UDPFS games list. Select a game and launch it — Neutrino is invoked automatically unless the game's Loader Core is <OPL>; SMB and NFS boot through OPL's own core unless the game is set to Neutrino.

Which core runs a network game

UDPBD and UDPFS (Files and IMG) launch via Neutrino by default, even when the global Default Loader Core is <OPL>. Set a game's Loader Core to <OPL> to run it on OPL's own core instead (ported from YAOPL). The selector stays open, and its Default entry means Neutrino on these tabs. If the Neutrino launch cannot start (no neutrino.elf, a .zso image, too many fragments), the game falls back to the OPL core; a missing or unwritable bsd toml still returns to the menu with its message.

On the OPL core the game keeps the network: after the IOP reset OPL reloads the same block driver the menu used, gives it the static PS2 IP from Settings → Network, and fakes the game's own DEV9 and SMAP modules. There is no RetroAchievements telemetry and no in-game UDPTTY on that path. UDPBD reads at most 16 KiB per request. If the block driver does not start, the screen blinks red and the console stops instead of hanging on black. Not tested on hardware yet.

UDPFS Files on the OPL core (RiptOPL #161, Open-PS2-Loader #1134) follows Neutrino's own design. The menu opens the game's ISO on the server and keeps it open across the IOP reset; in game OPL loads udpfs_smap, udpfs_ministack and udpfs_fhi, which finds the server again and reads that open file. The game waits up to 30 seconds for the server at start and retries a read after a dropped connection. VMCs work and save to the server: each card is opened read-write and kept open the same way, and a card the server will not open for writing (read-only share, file already open) offers the usual prompt to continue without it. If the PC server is restarted while a game runs, the game cannot reopen its files; restart the game (Neutrino has the same limit). Not tested on hardware yet.

SMB and NFS are different: they run on OPL's own core by default, need no Neutrino, and behave like the classic OPL network share. A game set to Neutrino (per game, or Default while the global Loader Core is Neutrino) launches through Neutrino's own SMB or NFS backend instead, which the Neutrino build in the release kits does not have yet. See SMB (network share) and NFS.

Per-game settings still work
UDPFS games support the full per-game settings screen in its Neutrino-aware mode: compat modes 1/2/3/5 (mapped to -gc), mode 7 (fix IOP buffer overrun, -gc=7), the Neutrino Video picker (-gsm), VMC, and free-text Neutrino Launch Args. OPL-core-only panels (GSM, PADEMU, OSD Language) show a "not used with the Neutrino core" notice. Text cheats use the same selection UI when the installed Neutrino runtime supports them; cheat images remain native-only. See Per-game Settings and Neutrino Core for details.

One NIC, one transport — how the four rows interlock

The PS2 has a single Ethernet adapter (SMAP), and every network transport — SMB, NFS, HTTP, UDPFS and UDPBD — loads a SMAP driver on it. Only one can own the adapter at a time, so RiptOPL exposes them as mutually exclusive values of one Protocol row rather than independent toggles. That replaces the old model, where a separate Network Boot toggle and an Ethernet (SMB) mode had to be greyed against each other. Network Connectivity decides whether the stack starts at all, and on the Network page the chosen protocol qualifies its own sub-rows (SMB Version is live only under SMB; Access is free only under UDPFS, and is value-locked to Files under SMB, HTTP and NFS and to IMG under UDPBD). Switching between them is just changing the Protocol value and saving. (The same one-transport-per-boot rule is why Access = Files vs IMG is a config-time choice, applied on the next restart.)

Local devices — USB, MX4SIO, iLink, internal HDD (APA / exFAT), and MMCE — are entirely independent of these rows and browse alongside whichever network protocol you pick (or none).

Game folder layout on the server

For the IMG mode (Access = IMG) and SMB, the PC server exports a FAT/exFAT volume the PS2 reads with the same folder conventions as a USB drive:

mass0:/  (device root — folders sit here directly by default)
  CD/          ← PS2 CD-ROM images (.iso)
  DVD/         ← PS2 DVD images (.iso)
  ART/         ← cover art (same naming as USB)
  CFG/         ← per-game config files
  VMC/         ← virtual memory cards (optional)
  POPS/        ← POPSTARTER.ELF and VCDs (UDPFS Files only; see PS1 setup)
  EMBER/       ← Ember runtime and games (where supported)
  APPS/        ← homebrew ELF files (optional)

The UDPFS Files mode uses the same CD/ + DVD/ layout, just without a disk image: point udpfsd -fsroot at a folder that contains CD/ and DVD/ subfolders of ISOs (OPL lists from <served>/CD + <served>/DVD, not the served root). Drop an ISO into CD/ or DVD/ and it appears in the UDPFS games list — no massN:, no fragment list, and server-dependent virtual ISO exposure (see the format limits below).

Can I use ZSO or UL-format images over UDPFS?

RiptOPL scans ISO/ZSO-style names, but Neutrino launches require ISO bytes: a direct .zso is refused, .cso/.chd names are not discovered, and UL split images have no Neutrino path. A server may transparently decompress a file only if it exposes an .iso entry with correct ISO contents and size. This is server-specific; verify its behavior. IMG and UDPBD expose raw disk sectors, so use ordinary ISO files in that filesystem.

Existing UDPBD setup stopped working after updating The Protocol row is set to something other than UDPBD (UDPBD is wire-incompatible with UDPFS, so a UDPFS pick won't talk to udpbd-server). Set Network → Protocol back to UDPBD (with Network Connectivity on Manual or Auto) and keep running the same udpbd-server on the PC — a config saved as UDPBD is preserved as-is, never migrated. (Alternatively, switch to UDPFS and run udpfsd instead — but that is a different protocol and server.)

For further reading see Neutrino Core (per-game settings, launch args).

SMB (network share)

Load PS2 (and PS1) games directly from a shared folder on a Windows PC, Linux Samba server, or NAS over your local network. RiptOPL's own core speaks SMB2/3 on a new install (SMBv1 for a settings file from before the SMB Version row), and that row in Network switches between them; a game on the Neutrino core can instead use Neutrino's experimental SMB 3.0 client. No USB drive required — the PS2 mounts the share and reads ISOs straight off it.

SMB and Network Boot share the same adapter
The PS2 has one Ethernet port and one network driver. SMB (ETH) and Network Boot (UDPBD/UDPFS) are mutually exclusive — selecting one in Game Sources excludes the others. If you switch, you must save and restart for the change to take effect. See One NIC, one transport for how the rows interlock.

What you need

  • A PS2 with a network adapter (PS2 HDD adaptor with Ethernet, or a compatible third-party adapter).
  • A PC, NAS, or Linux/macOS box that serves the share in the dialect you select on OPL's core, SMB2/3 (a new install's default) or SMBv1 (the experimental Neutrino SMB path needs SMB 3.0 on port 445 instead). On Windows, the recommended path is the PS2 Servers all-in-one launcher; Samba and compatible NAS shares remain supported.
  • Both devices on the same local network (wired is strongly recommended — Wi-Fi via a media bridge is possible but adds latency).
  • A static IP address for the PS2, or DHCP with a known/stable lease. A static IP is far simpler and avoids reconnection surprises.
Recommended on Windows: PS2 Servers
RiptOPL no longer embeds a PC SMB server. Open PS2-Servers.url from the release package or visit PS2 Servers, choose the SMB card that matches SMB Version, select your games folder and follow the protocol-specific IP, port, share and credential values the launcher displays. Use its SMBv2 card (SMB up to 2.1) with SMB2/3, or its SMBv1 card with SMBv1. The SMBv1 card implements the OPL-compatible SMBv1 subset directly and does not require you to enable Windows' built-in SMB1 feature. With SMB2/3 OPL's core falls back to SMB 3.0 when a server refuses 2.x, so an SMBv3 card that does not require signing answers too; its SMBv3 card on port 445 is also what the Neutrino SMB path needs. Samba/NAS users may need min protocol = NT1 if their server defaults have been tightened.

1. Set up the SMB server and share

PS2 Servers: download its packaged app, choose the SMBv2 card (the SMBv1 card if SMB Version is SMBv1), select your games folder and click Start. Use the exact connection settings shown by the launcher. The manual share instructions below are for Samba, a NAS, or another already-configured SMB server.

Create a folder

Create a folder to act as the OPL root — e.g. C:\PS2SMB on Windows or /srv/ps2smb on Linux. Give it the standard OPL subfolder layout (OPL will create missing folders automatically on first connect, but it helps to have them ready):

PS2SMB\
  CD\       ← PS2 CD-ROM games (blue-bottom discs, <700 MB ISOs)
  DVD\      ← PS2 DVD5 / DVD9 ISOs
  POPS\     ← PS1 *.VCD files + POPSTARTER.ELF (for PS1 games)
  ART\      ← cover art
  CFG\      ← per-game config files
  VMC\      ← Virtual Memory Card images
  THM\      ← themes
  CHT\      ← cheat files
  APPS\     ← homebrew ELFs

Grant the access your features need

Read access is required for game loading. Write access is also needed to create support folders, save configuration changes or save to VMCs on the share. Copy the endpoint and credentials shown by your server.

Linux / Samba: add a share block to /etc/samba/smb.conf — for example:

[PS2SMB]
   path = /srv/ps2smb
   browseable = yes
   writable = yes
   guest ok = yes
   min protocol = NT1

Then run sudo systemctl restart smbd. If you use a password, set up a Samba user with sudo smbpasswd -a <username> instead of using guest ok = yes.

The min protocol = NT1 line above is there to let a modern Samba still answer SMBv1, which OPL's core needs on SMBv1. With SMB Version on SMB2/3, drop that line. The Neutrino SMB path uses SMB 3.0 on port 445, which Samba offers by default.

Place your game ISOs

Copy PS2 ISOs into DVD\ (for DVD games) or CD\ (for CD-ROM games). USBExtreme/USB Advance split-format games (ul.*) work too, but single-file ISOs are simpler over a network. There is no per-file size limit on the SMB path — DVD9 dual-layer ISOs (~8 GB) are fine.

After filling in the fields, press OK to save. The dialog also has a Reconnect button: it saves and immediately retries the SMB connection without a full restart. If anything changed on the server (new files, credentials updated), Reconnect refreshes the game list without rebooting.

3. Enable SMB in Game Sources

The Network page stores the how: protocol, address and credentials. Game Sources stores the whether. For SMB, set Network Connectivity on Game Sources to Manual or Auto and the Protocol under it to SMB, then on the Network page set SMB Version to the dialect your server speaks:

RowValuesWhat it does
Network Connectivity (Game Sources)Off / Manual / AutoThe network start mode, using the same three options as every other device. Off loads no network transport at all. Manual registers the ETH Games tab and connects when you navigate into it — boot stays fast and you only pay the connection cost on entry. Auto brings the stack up during startup instead.
Protocol (Game Sources, under Network Connectivity, and Network)SMB / UDPFS / UDPBD / HTTP / NFSWhich transport owns the single Ethernet adapter. One setting shown on both pages. SMB is the network-share client documented in this section, and NFS has its own section; UDPFS and UDPBD select Network Boot instead — see The Network rows and the NIC interlock.
SMB Version (Network)SMBv1 / SMB2/3Which SMB dialect to speak. A new install starts on SMB2/3; a settings file from before this row keeps SMBv1. Live only while Protocol is SMB, and greyed out otherwise, but the value is kept. See SMB Version below.

SMB is interlocked with Network Boot
Because Protocol is one exclusive picker, SMB and Network Boot (UDPBD/UDPFS) are mutually exclusive by construction: selecting SMB rules out UDPBD/UDPFS, and selecting either UDP transport rules out SMB. Both require the PS2's single Ethernet adapter; only one can be active at a time. The interlock is enforced both in the UI and at runtime in ethsupport.c, which refuses to bring up the SMB stack while UDPBD holds the adapter.

SMB Version

The SMB Version row picks the dialect for the whole SMB session on OPL's core. SMB2/3 and SMBv1 each use their own driver for both halves of the SMB path:

HalfSMBv1SMB2/3 (a new install's default)
Browsing the share in the menu (the ETH Games tab)PS2SDK's smbman.irxRiptOPL's smb2man.irx, built on usmb2 by Ronnie Sahlberg (MIT; see License)
Reading the disc image in gameThe SMB1 reader inside cdvdmanRiptOPL's own SMB2 reader inside cdvdman

Both drivers register the same smb0: device, so the folder layout, the ETH prefix and the config keys are the same whichever one is loaded. Only one is resident at a time, and the game always uses the dialect the menu is browsing with. If the SMB2/3 driver cannot load, browsing falls back to SMBv1. SMB2/3 logs on with NTLMv2 (guest and anonymous logons work too) and signs its requests when the server requires signing, as Windows 11 24H2 does by default. Not tested on hardware.

Your server must speak the dialect you pick
The session does not negotiate between SMBv1 and SMB2/3. Under SMB2/3, an SMBv1-only server (such as the PS2 Servers SMBv1 card) lists no games; under SMBv1, a server with SMB1 turned off lists none. Put the row on the dialect your server answers.
What SMB2/3 on OPL's core speaks, and its limits
  • Dialects: SMB 2.0.2 and 2.1 first; if the server refuses those, SMB 3.0 and 3.0.2, unsigned. A server that accepts only SMB 3.1.1 is not reached, and neither is a server that refuses 2.x and requires signing on SMB 3.x (SMB 3.x signs with AES-CMAC, which RiptOPL does not implement): browsing fails to log on. Windows, Samba and the PS2 Servers SMBv2 card all still offer 2.x, and over 2.x a server that requires signing (Windows 11 24H2) is signed for.
  • Server address: the driver connects to an IPv4 address. A NetBIOS name (Address Type) still works, because the menu looks it up before connecting; DNS host names are not supported.
  • No share list: SMB2/3 cannot list the server's shares, so the Share name must be typed in on the Network page.
  • User name and password: Latin-1 characters only (nothing above U+00FF); a credential with other characters is refused at logon rather than sent wrongly. The Network page keeps up to 31 bytes of each.
Changing the dialect needs a restart if an SMB driver is loaded
Each network transport loads its modules once per boot. If an SMB driver is already loaded this session, changing SMB Version offers a restart, as a protocol change does. From a cold boot the new dialect applies straight away.

SMB through Neutrino (experimental)

A game whose Loader Core is Neutrino, or Default while the global Loader Core is Neutrino, launches from the share through Neutrino's own SMB driver instead: the backend Ronnie Sahlberg added to Neutrino (ps2max32/neutrino PR #236, merged 2026-10-31), built on his usmb2 client. At launch RiptOPL writes the menu's network, server and share settings into config/bsd-smb.toml in the Neutrino folder, closes its own SMB session and starts Neutrino with -bsd=smb.

  • Install a complete Neutrino folder built after that merge (with config/bsd-smb.toml and both SMB modules) on a memory card or USB, not on the share. The release kits bundle upstream's latest development build, which is still v1.8.0-61-g7be8de2 from 2026-08-31 (checked 2026-11-12) and has no SMB backend, so with the kit as shipped these games run on OPL's core with a warning, until upstream publishes a newer build or you install one built from upstream's master yourself.
  • The server must offer SMB 3.0 on TCP 445 with NTLM login and no signing or encryption, such as the PS2 Servers SMBv3 card on port 445. The SMB Version row does not apply.
  • Use plain ASCII user names and passwords of at most 31 characters.
  • A game with a VMC, a ZSO or UL image, a port other than 445, or a Neutrino folder without the SMB files launches on OPL's core with a warning instead.
  • The RetroAchievements kit's NULD (formerly ORBIT) runtime does not have this backend yet.

Full setup and limits: SMB through Neutrino. Not tested on hardware.

5. PS1 games over SMB

The L3 PS1 view works on SMB just like USB: with PS2/PS1 Game Display set to Both (L3) or Mixed (see Interface), press L3 on the ETH Games page to switch between your PS2 disc list and your PS1 list (VCDs and Ember games). With it locked to PS2, PS1 games are not shown. Place your VCDs (and POPSTARTER.ELF) in the POPS\ subfolder of the share. Ember games go in EMBER\games\<Game Name>\ beside it and need none of the memory-card setup below.

Launching a PS1 game over SMB has one extra requirement: POPSTARTER needs its own copy of the network configuration and its SMB modules on the memory card — it cannot read them from the share at launch time.

Copy the SMB modules to the memory card

The release package's canonical POPS/ folder contains the four network IRX modules POPSTARTER needs for SMB: smbman.irx, ps2ip.irx, ps2smap.irx, and ps2dev9.irx. They must end up in mc0:/POPSTARTER/ (or mc1:/POPSTARTER/). If the share's own POPS/ folder holds them, an SMB VCD launch copies any that are missing to the card for you; it never replaces a file already on the card, and it refuses a copy that would fill the card. Otherwise copy them yourself. OPL checks for all four on one card before an SMB VCD launch and warns you rather than hanging if any are missing.

Set up the POPSTARTER network config

Open POPSTARTER Network Settings, from Settings → Network or Settings → PS Emulation Settings. It edits POPSTARTER's own mc?:/POPSTARTER/IPCONFIG.DAT and SMBCONFIG.DAT in the format POPSTARTER expects, so you do not need to edit those files by hand.

The screen shows what those files already contain, or says none were found. Import from SMB POPS Directory copies both from the connected share's POPS folder. On OK, only the values you changed are written, to the card the existing files came from, and replacing an existing configuration asks first. On a first setup, with neither file on the card, saving the SMB values writes IPCONFIG.DAT too, as DHCP unless a complete static IP is entered. If writing fails, OPL shows an error message.

The PS1 leg is SMBv1 regardless of the SMB Version row
POPSTARTER uses its own SMBv1 modules (the module set OPL checks for on the memory card is smbman.irx) and reads its own SMBCONFIG.DAT, not OPL's dialect choice. So a PS1 VCD launched over SMB needs a server that answers SMBv1, even with OPL set to SMB2/3 for PS2 games. An SMBv3 card on port 445 that serves Neutrino games does not serve PS1 VCDs.

For deeper PS1 coverage — cover art by PS1 disc ID, the four PS2/PS1 Game Display modes, and BDMA module equipping for block devices — see PS1 Games (VCD).

Does the BDMA exFAT equip apply to SMB?

No. The BDMA equip copies block-device driver modules for POPSTARTER to use when reading an exFAT drive. SMB is a pure network path — there is no block device involved. The BDMA Mode and BDMA Source settings on PS Emulation Settings have no effect on an SMB VCD launch. The only prerequisite for PS1 over SMB is the four network IRX modules above plus the POPSTARTER network config files.

6. SMB vs. Network Boot — the NIC interlock

The PS2's DEV9 expansion bay contains the Ethernet adapter (SMAP). There is only one, and only one network driver stack can own it at a time.

  • SMB active: OPL loads its own network stack (NETMAN + SMAP + PS2IP) and connects to the share. UDPBD/UDPFS cannot load.
  • Network Boot active: Neutrino's UDPBD or UDPFS driver owns the adapter. The SMB stack will not load (enforced both in the Game Sources UI and by a runtime guard in ethsupport.c).

To switch from SMB to Network Boot (or vice versa), go to Game Sources, change the Protocol row, save, and restart OPL. You do not need to change any hardware.

The two approaches serve different use cases: SMB lets any device on the LAN (NAS, always-on PC, server) host your library with no special server software beyond a standard file share; Network Boot via UDPBD/UDPFS requires a dedicated server process running on a PC during play but streams the disc image at block-device level (Neutrino handles the disc emulation, not OPL's loader core). See Access — Files vs IMG and Which core runs a network game above for details.

7. Common problems

SymptomLikely cause & fix
OPL shows "Network startup error: CONN" or similar The PS2 cannot reach the server. Check: server IP is correct, server is on and reachable, the server answers the dialect selected in SMB Version, no firewall is blocking the configured port, and the PS2 IP is valid. With PS2 Servers, copy the protocol-specific IP and port shown by its launcher rather than assuming RiptOPL's default port (445 on a new install).
ETH Games tab lists nothing at all on SMB2/3 Usually a dialect mismatch: the server speaks only SMBv1, or only SMB 3.1.1, or refuses SMB 2.x and requires signing on SMB 3.x. The session does not negotiate between SMBv1 and SMB2/3. Set Network → SMB Version to SMBv1 (needed for the PS2 Servers SMBv1 card), or use a server that offers SMB 2.0.2 or 2.1, such as the PS2 Servers SMBv2 card. If an SMB driver was already loaded when you changed the row, accept the restart.
OPL shows "LOGON" error Wrong username or password. Try GUEST / empty password for a guest share, or confirm the account credentials. Check that the Samba user (if Linux) has been added with smbpasswd.
OPL shows "SHARE" error (open share failed) The share name does not match. Verify the exact share name on the server (case-sensitive on Linux). RiptOPL's default share name is games (stock OPL uses PS2SMB).
Game list is empty even after connecting Check that ISOs are in the correct subfolder (DVD\ or CD\) and that the user has read access to those folders. On Windows, NTFS permissions and share permissions are separate — verify both.
Games load slowly or stutter Wired Ethernet is strongly recommended. If using a media bridge or powerline adapter, test with a direct cable run first. Neither dialect compresses or caches on OPL's side; all disc reads go across the wire in real time.
DHCP fails / no IP assigned OPL waits up to 30 seconds for a valid DHCP lease. If it times out, it logs "Unable to get valid IP address via DHCP." Switch to a static IP if your DHCP server is slow or if the PS2's MAC is not being offered a lease.
PS1 VCD launch fails or hangs Check that the four SMB IRX modules (smbman.irx, ps2ip.irx, ps2smap.irx, ps2dev9.irx) are present in mc?:/POPSTARTER/, and that the network config files (IPCONFIG.DAT, SMBCONFIG.DAT) have been written. Set them up from POPSTARTER Network Settings on Settings → Network. Note that this leg is SMBv1 whatever SMB Version is set to, so the server must still answer SMBv1 for PS1 VCDs.
A game freezes at its next disc read after the console sat idle (paused, or waiting on a menu) Samba sends a NetBIOS keepalive every few minutes. While the game reads nothing, each one waits in the in-game network stack's small buffer pool (8 buffers). After about eight of them the PS2 stops answering, and Samba closes the connection. Turn those keepalives off and let TCP keep the connection alive: in the [global] section of smb.conf set 
keepalive = 0
socket options = SO_KEEPALIVE=1 TCP_NODELAY=1
and restart Samba. A reporter measured the eight keepalives with Wireshark and found these settings held for three hours; this is not yet verified on our side. A read cut off this way now fails instead of locking the game up for good, but the game still cannot continue, so the server settings are the real fix. Diagnosis and workaround documented by belomaxorka / YAOPL (36e07200).
Windows: share works from PC but PS2 cannot connect Use PS2 Servers instead of enabling Windows' built-in SMB1 feature, and match the IP, port, share and credentials shown by its launcher. Confirm its firewall rule allows the selected SMB port on your private LAN.

NFS (network export)

Load PS2 games, and Ember PS1 games, from an NFS version 4.0 export on TCP port 2049, such as the NFS card of PS2 Servers v0.9.3 or later. Other NFS version 4.0 servers (Linux, a NAS) have not been tried yet. The OPL core reads the game with its NFS reader, built on Ronnie Sahlberg's unfs4.

New and untested on a console
NFS is host-tested only, against the PS2 Servers NFS server. It has not been tested on a real PS2 or in PCSX2, on either core, or against any other NFS server. RiptOPLite has no NFS.

Setting it up

Serve an export

In PS2 Servers, choose the NFS card, select the folder that holds CD/ and DVD/, and click Start. Its export is /. To let RiptOPL save, rename or delete on it, also turn on the card's Allow writes switch. On another server, export the folder over NFS version 4.0.

Pick NFS in RiptOPL

Set Network Connectivity to Manual or Auto and Protocol to NFS under Settings → Game Sources, then fill in the Network page.

Network rowWhat to enter
- NFS Server -: Address Type, AddressThe same server address rows as SMB: an IP address or a NetBIOS name. NFS has no port, user or password rows.

NFS through Neutrino (experimental)

A game whose Loader Core is Neutrino, or Default while the global Loader Core is Neutrino, launches through Neutrino's own NFS backend, also by Ronnie Sahlberg (ps2max32/neutrino PR #240, merged 2026-11-12). No Neutrino release or development build has this backend yet: the build the kits bundle is from 2026-08-31. Until one does, these games run on the OPL core with the message "This Neutrino has no NFS support -- launching with the OPL core." A VMC, a ZSO or USB Extreme image, neutrino.elf only on the export, or an export or path past Neutrino's limits also keep the game on the OPL core with a message. PS1 over NFS

Ember games launch over NFS: Ember keeps the I/O processor and reads its ELF, bios.bin and the game folder through the menu's NFS connection, as it does over SMB. Put the EMBER/ folder in the export's game folder, beside CD/ and DVD/. While NFS Writes is Off, Ember's game settings and Rename are hidden on PS1 rows, and a warning says Ember cannot keep memory card saves in the game's folder. POPSTARTER (.VCD) cannot launch over NFS, because it restarts the I/O processor and has no NFS driver (on the network it reaches SMB, and UDPFS Files through UDPFS Assault); the NFS page lists Ember games only. Use SMB for .VCD games.
